# korea-law — 법령은 부르고, 기억으로 답하지 않는다

MCP 서버 `korea-law` (저장소 `{REPO}`) 가 전역 등록돼 있다.
LLM 호출이 없는 파이썬이 법제처를 부른다. 토큰은 결과를 읽는 데만 든다.

## 도구 고르기

| 하고 싶은 것 | 도구 |
|---|---|
| 주제 하나를 처음 훑기 (용어·8축·하위법령·별표) | `law_brief` |
| 법 이름 → 법령ID·MST (띄어쓰기·약칭·구법 포함) | `law_find` |
| 낱말이 실제로 쓰인 조문 | `law_term` |
| 법률 → 시행령·시행규칙·조례·행정규칙 | `law_tree` |
| 별표·서식 (수치 기준은 대부분 별표에 있다) | `law_annex` |
| 옛 법인가, 무엇으로 바뀌었나 | `law_history` |
| 법·조례·행정규칙·판례·헌재·해석례·심판례·감사원 8축 | `law_search` |
| 어떤 API 가 있나 (설명서 195건) | `law_api` |
| 위에 없는 API 직접 호출 | `law_api` 로 target 확인 → `law_call` |

## 절대 규칙 — 모르는 것을 모른다고 말한다

1. 응답에 `"complete": false` 가 있으면 **"없다", "전부다", "해당 조문은 존재하지 않는다"라고 답하지 마라.**
   `why` 를 사용자에게 그대로 알리고, 받은 만큼(`partial`)만 "일부"라고 밝혀서 쓴다.
2. `경고` 에 데모 키가 뜨면 결과가 제한됐을 수 있다고 알린다.
3. `law_term` 0건은 "관련 조문 없음"이 아니라 "용어 사전 미등재"다 → `law_search` 로 본문검색을 한다.
4. 별표는 시행령·시행규칙에 붙는다. 법률 본문만 보고 수치를 말하지 않는다.
5. `law_history` 의 승계 후보는 **후보**다. 단정하지 않는다.
6. 인용할 때는 법령명·조번호·시행일자를 같이 적는다.

## 파이썬에서 직접

```python
import sys; sys.path.insert(0, r"{REPO}")
import law_kit
law_kit.terms.articles("도시혁신구역")
```
명령줄: `python -m law_kit brief <주제>` (저장소 폴더에서).

첨부(HWP/PDF)를 받으면 모델 컨텍스트에 통째로 넣지 말고 `kordoc`/`anydoc` 로 Markdown 으로 바꿔서 필요한 부분만 읽는다.
